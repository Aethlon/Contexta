# How to Send Data to Contexta

How to get conversation turns, tool logs, and historical chat transcripts into Contexta for extraction, truth maintenance, and durable indexing.

## Entry points

| Interface | Protocol | Best for |
| :--- | :--- | :--- |
| **Python SDK** | HTTP client | Python agents (LangChain, LlamaIndex, custom loops) |
| **TypeScript SDK** | HTTP client | Node, Next.js, Bun, Deno, edge runtimes |
| **REST API** | `POST :8000/v1/observations` | Direct integrations, webhooks, microservices |
| **Go gateway** | `POST https://localhost:8443/v1/observations` | Only if you deliberately run `--profile edge` for TLS termination |
| **MCP server** | `:8765/sse` | Cursor, Windsurf, Claude Desktop |
| **Batch** | `POST :8000/v1/observations/batch` | Bulk seeding, historical imports, benchmark harnesses |

Every path funnels into the same validated `ObservationPayload` schema and the same nine-stage pipeline.

## The data contract

```json
{
  "user_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "organization_id": "96d29395-6d90-4ba2-9eed-6a851e0290c1",
  "session_id": "c9bf9e57-1685-4c89-bafb-ff5af830be8a",
  "messages": [
    {"role": "user", "content": "I am moving to Seattle next month and adopting a golden retriever named Rusty."},
    {"role": "assistant", "content": "Congratulations on the move to Seattle and your new golden retriever, Rusty!"}
  ],
  "occurred_at": "2024-10-12T14:45:00Z",
  "timezone": "America/Los_Angeles",
  "metadata": {"agent_id": "agent-orchestrator-01", "channel": "slack"}
}
```

### Required

| Field | Type | Notes |
| :--- | :--- | :--- |
| `user_id` | uuid | **Must equal the actor bound to your API key**, or `403`. |
| `organization_id` | uuid | Must equal the key's organization, or `403`. |
| `session_id` | uuid | **Required.** Create one with `POST /v1/sessions` or generate your own. |
| `messages` | `list[object]` | `{role, content}` turns. |

`session_id` is **not** optional and is **not** auto-generated by the observation route. The old docs claimed otherwise; `ObservationPayload` marks it required.

### Optional but worth using

| Field | Type | Why |
| :--- | :--- | :--- |
| `occurred_at` | datetime | Lets the temporal normalizer ground *"next month"* instead of guessing. |
| `observed_at` | datetime | Separates when it happened from when you saw it. |
| `timezone` | IANA string | Required to resolve relative expressions correctly. Alias: `event_timezone`. |
| `temporal_precision` | string | Alias: `precision`. |
| `temporal_basis` | string | Alias: `basis`. |
| `source_id`, `message_id` | any | Provenance, carried into `structured_data.temporal_source`. |
| `source_start`, `source_end`, `source_span` | int / object | Span within the source. Alias: `span`. |
| `original_text`, `normalized_text` | string | Redacted before they reach the LLM. |
| `metadata` | object | Opaque, carried to audit and telemetry. |
| `policy` | string | Recorded as an opaque string. There is no policy registry. |

`messages` entries are `{"role", "content"}` dicts. Role values are not validated; `user`, `assistant`, and `tool` are what the extractor expects.

## REST

```bash
curl -X POST http://localhost:8000/v1/observations \
  -H "Authorization: Bearer $CONTEXTA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "'$CONTEXTA_ACTOR_ID'",
    "organization_id": "'$CONTEXTA_ORG_ID'",
    "session_id": "c9bf9e57-1685-4c89-bafb-ff5af830be8a",
    "messages": [
      {"role": "user", "content": "I will start my masters in Clinical Psychology at UW in September 2025."}
    ],
    "metadata": {"source": "onboarding"}
  }'
```

Response — note this is **not** the shape the old docs showed:

```json
{
  "job_id": "e305e552-8da5-42cb-b7ff-cb54e3d939a8",
  "observation_id": "e305e552-8da5-42cb-b7ff-cb54e3d939a8",
  "status": "accepted"
}
```

There is no `task_id`, no `memories_created`, and no `cortex_evaluated`. The `202` is returned **after** the observation, its source turns, and the outbox event are committed, so `memories_created` could not honestly be non-zero yet.

Poll for completion:

```bash
curl http://localhost:8000/v1/observations/$JOB_ID -H "Authorization: Bearer $CONTEXTA_API_KEY"
```

## Python SDK

```python
from contexta_client import Contexta

client = Contexta.from_env()

result = client.observe(
    user_id=ACTOR_UUID,
    session_id=session_id,
    messages=[
        {"role": "user", "content": "I am lactose intolerant, so please avoid dairy recommendations."},
        {"role": "assistant", "content": "Noted! I'll only recommend dairy-free meals."},
    ],
    metadata={"platform": "web_chat"},
)
print(result.job_id, result.status)
```

The class is `Contexta`, not `ContextaClient`, and the package is `contexta_client`, not `contexta`. The old docs had both wrong.

## TypeScript SDK

```ts
import { Contexta } from "@contexta/client";

const client = Contexta.fromEnv();

await client.observe({
  userId: ACTOR_UUID,
  sessionId,
  messages: [
    { role: "user", content: "I prefer working in Go and React." },
    { role: "assistant", content: "Great! I'll keep your stack preferences in mind." },
  ],
});
```

The package is `@contexta/client`, not `@contexta/sdk`, and the class is `Contexta`, not `ContextaClient`.

## Batch ingestion

```bash
curl -X POST http://localhost:8000/v1/observations/batch \
  -H "Authorization: Bearer $CONTEXTA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"observations": [ { … }, { … } ]}'
```

Up to **100** per call, not 50. Invalid items come back in `errors` with index-qualified field paths; the valid ones still ingest.

## Historical transcripts and benchmark corpora

For imports, anchor every turn explicitly rather than relying on ingestion time:

```python
from uuid import uuid4

from contexta_client import Contexta

client = Contexta.from_env()

for session in historical_sessions:
    messages = [
        {
            "role": turn["speaker"],
            "content": f"[Date: {session.started_at}] {turn['text']}",
        }
        for turn in session["turns"]
    ]
    client.observe(
        user_id=user_id,
        session_id=str(uuid4()),
        messages=messages,
        occurred_at=session["started_at"],
        timezone="UTC",
    )
```

That is the shape the LoCoMo harness uses. Prefer the structured `occurred_at` / `timezone` fields over a `[Date: …]` prefix in the prose where you can — the extractor reads both, but only the structured field is guaranteed to reach the temporal normalizer.

## Limits and errors

| Situation | Response |
| :--- | :--- |
| Body over 1 MiB | `422` `Payload exceeds maximum allowed size.` |
| Batch over 100 items | `422` `Batch item limit exceeded.` |
| Body is not a JSON object | `422` `Expected a JSON object.` |
| Missing required field | `422` with `errors[].field` |
| `user_id` / `organization_id` disagree with the key | `403` |
| Replayed idempotency key with a different payload | `409` |
| Storage unavailable | `503` |

## What happens to your data, in order

1. **Redact** — fail-closed secret scrub, before anything else.
2. **Extract** — discrete typed facts with confidence and temporal precision.
3. **Dedup** — in-batch merge, then a check against the `fact_key` slot.
4. **Score** — importance and confidence; low-value extractions drop out here.
5. **Graph** — entity resolution and typed edges.
6. **Reconcile** — contradicted facts supersede, with lineage recorded.
7. **Embed** — local 1024-d Qwen3 vector.
8. **Retrieve** — dense + lexical + graph, fused, on the next query.

If the redaction gate errors, the observation is rejected. It is never forwarded unredacted.
