# LangChain Integration

Contexta implements LangChain's `BaseChatMessageHistory` for LCEL chains, so it drops into `RunnableWithMessageHistory`.

## Installation

The adapter ships **inside** the `contexta-client` package in this repository. There is no separate `contexta-langchain` distribution, and the import path is `contexta_client.adapters.langchain` (not `CONTEXTA_langchain`).

```bash
pip install -e clients/python
pip install "langchain>=0.3"
```

## Python

```python
from langchain.schema import AIMessage, HumanMessage
from langchain.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain.schema.output_parser import StrOutputParser
from langchain.schema.runnable import RunnableWithMessageHistory

from contexta_client import Contexta
from contexta_client.adapters.langchain import contextaChatHistory

client = Contexta.from_env()
```

`contextaChatHistory(client, user_id, session_id, token_budget=None)`. It raises `ImportError` at construction if `langchain>=0.3` is not importable.

```python
chain = (
    ChatPromptTemplate.from_messages([
        ("system", "{contexta_context}"),
        MessagesPlaceholder(variable_name="history"),
        ("human", "{input}"),
    ])
    | llm
    | StrOutputParser()
)

def get_context(session_id: str) -> str:
    ctx = client.context(
        user_id=ACTOR_UUID,
        session_id=session_id,
        token_budget=1500,
    )
    return ctx.to_system_prompt()

with_history = RunnableWithMessageHistory(
    chain,
    lambda session_id: contextaChatHistory(
        client,
        user_id=ACTOR_UUID,
        session_id=session_id,
    ),
    input_messages_key="input",
    history_messages_key="history",
)

result = with_history.invoke(
    {
        "input": "What database do I prefer?",
        "contexta_context": get_context(session_id),
    },
    config={"configurable": {"session_id": session_id}},
)
```

`get_context` takes a **session id**, not a query text. `GET /v1/memories/context` has no `query` parameter, so if your integration is passing one, it is being dropped by the server.

### Legacy memory API

`contextaMemoryLegacy(client, user_id, session_id, memory_key="chat_history", token_budget=None)` wraps the same `contextaChatHistory` and exposes a `buffer` property for LangChain's deprecated `Memory` interface.

## TypeScript

```ts
import { Contexta } from "@contexta/client";
import { contextaChatHistory } from "@contexta/client/adapters/langchain";

const client = Contexta.fromEnv();

const history = new contextaChatHistory(
  client,
  ACTOR_UUID,          // userId
  ORGANIZATION_ID,     // organizationId — positional, unlike Python
  sessionId,
  1500,                // tokenBudget
);
```

The TypeScript constructor is **positional** and takes five arguments including `organizationId`; the Python constructor takes four and reads the organization from the client. That asymmetry is real, not a doc error.

## Gotcha

`user_id` must equal the actor bound to your API key. The adapter cannot know it, so pass the same UUID you minted the key with or every history load returns `403`.
