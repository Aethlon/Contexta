# SDK Overview

Contexta ships two first-party SDKs: Python (`contexta-client`) and TypeScript (`@contexta/client`). Both are in this repository, both are MIT-licensed, and both expose the same **32 public methods** — the list is asserted against `clients/public-api.manifest.json` by both test suites, so they cannot drift apart silently.

## Installation

The published packages are not on PyPI or npm yet. Install from this repository:

```bash
# Python
pip install -e clients/python

# TypeScript
npm install ./clients/typescript
```

## Naming

`Contexta` and `AsyncContexta` are the canonical class names in both languages. The historical lowercase `contexta` / `Asynccontexta` still import and work, but emit a deprecation warning in Python and a single `console.warn` in TypeScript. Use the capitalised forms.

## Configuration

Both SDKs read these automatically:

```env
CONTEXTA_API_KEY=mk_live_…
CONTEXTA_API_URL=http://localhost:8000/v1
CONTEXTA_ORGANIZATION_ID=…        # required by context() and create_session()
CONTEXTA_TIMEOUT_MS=30000
CONTEXTA_MAX_RETRIES=3
CONTEXTA_TELEMETRY=true
CONTEXTA_VERIFY_TLS=true
CONTEXTA_CA_BUNDLE=…
```

`CONTEXTA_API_URL` defaults to `https://api.contexta.dev/v1`. **There is no hosted Contexta API** — for a self-hosted install, set it to your own `http://localhost:8000/v1`.

Or pass options directly:

```python
from contexta_client import Contexta

m = Contexta(
    api_key="mk_live_…",
    base_url="http://localhost:8000/v1",
    organization_id="…",
    timeout=30.0,
    max_retries=3,
)
```

```ts
import { Contexta } from "@contexta/client";

const m = new Contexta({
  apiKey: "mk_live_…",
  baseUrl: "http://localhost:8000/v1",
  organizationId: "…",
  timeout: 30000,
  maxRetries: 3,
});
```

Note the Python option is `base_url` and the TypeScript option is `baseUrl` — they differ from the constructor argument names the dashboard's setup panel shows, which is a known doc bug in the console.

## Initialisation

```python
from contexta_client import Contexta, AsyncContexta

m = Contexta.from_env()
am = AsyncContexta.from_env()
```

```ts
import { Contexta } from "@contexta/client";

const m = Contexta.fromEnv();
// or: new Contexta({ apiKey: "mk_live_…" })
```

Both clients work as context managers, so the offline buffer drains and connections close automatically:

```python
with Contexta.from_env() as m:
    …
```

```ts
import { withContexta } from "@contexta/client";

const prompt = await withContexta({ apiKey }, async (memory) => {
  const ctx = await memory.context({ userId, organizationId, sessionId });
  return ctx.toSystemPrompt();
});
```

### Not working in v1.5

These five methods exist in both SDKs but call endpoints that no longer exist. They will return `404` against a v1.5 server:

| Method | Dead endpoint |
| :--- | :--- |
| `list_policies`, `register_policy` | `GET`/`POST /v1/policies` |
| `register_schema` | `POST /v1/schemas` |
| `keys rotate` (CLI) | `POST /v1/keys/{id}/rotate` |
| `usage` (CLI) | `GET /v1/usage` |
| `projects list`/`create` (CLI) | `GET`/`POST /v1/projects` |

Rotation is create-then-revoke. Usage has no replacement because there is no metering.

## Error handling

```python
from contexta_client import (
    contextaError,
    AuthenticationError,
    AuthorizationError,
    ValidationError,
    NotFoundError,
    ConflictError,
    QuotaExceeded,
    RateLimited,
    ServerError,
)
```

```ts
import {
  contextaError, AuthenticationError, AuthorizationError, ValidationError,
  NotFoundError, ConflictError, QuotaExceeded, RateLimited, ServerError,
} from "@contexta/client";
```

`QuotaExceeded` is still exported for source compatibility, but nothing in v1.5 ever returns a plan limit — there is no quota.

## Retries and durability

Both clients:

- send an `Idempotency-Key` on every write,
- retry `429`, `5xx`, and network failures with exponential backoff, honouring `Retry-After` (Python: `retry_after or 2 ** attempt`; TypeScript: `min(1000 * 2 ** attempt + jitter, 30_000)`),
- fall back to a durable on-disk queue (`~/.contexta/buffer.jsonl` in Python) when the network is down.

```python
m.flush()   # drain the offline queue; returns entries replayed
m.close()   # release connections; safe to call twice
```

```ts
const replayed = await memory.flush();
memory.close();
```

## TLS

Certificate verification is on by default and disabling it is an explicit opt-in, never implicit. To trust the optional self-signed local gateway, supply its CA:

```python
m = Contexta(api_key="…", ca_bundle_path="./certs/cert.pem")
```

```ts
const memory = new Contexta({ apiKey, tls: { caPath: "./certs/cert.pem" } });
```

Supplying both a CA bundle and `verify_tls=False` raises a `ValueError` in Python rather than silently weakening verification.

## Runtimes

The TypeScript SDK runs on Node 18+, Vercel Edge Runtime, Cloudflare Workers, Bun, Deno, and modern browsers, with **zero required dependencies** — native `fetch`, `crypto`, and `AbortSignal.timeout`. `undici` is an optional peer dependency used only for custom TLS configuration on Node; anywhere `undici` is unavailable, or if you already have a TLS-configured `fetch`, pass `fetch` instead.

## Telemetry

Default-on, opt-out via `CONTEXTA_TELEMETRY=false` or `telemetry: false`.

To be precise about what that means: it controls a `User-Agent` version header (`contexta-python/<version>` or `contexta-sdk-ts/<version>`) and local per-endpoint counters. **Nothing is sent to a Contexta service**, because there is no Contexta service. No keys, no content, and no user IDs leave your process.

## Adapters

**Python** — OpenAI, Anthropic, LangChain, LlamaIndex:

```python
from contexta_client.adapters.openai import contextaMemory, contextaAssistantRunner
from contexta_client.adapters.anthropic import contextaMemory, contextaChat
from contexta_client.adapters.langchain import contextaChatHistory
from contexta_client.adapters.llamaindex import contextaChatMemory
```

**TypeScript** — OpenAI, Anthropic, LangChain, Vercel AI:

```ts
import { contextaMemory, contextaAssistantRunner } from "@contexta/client/adapters/openai";
import { contextaMemory } from "@contexta/client/adapters/anthropic";
import { contextaChatHistory } from "@contexta/client/adapters/langchain";
import { contextaMemory } from "@contexta/client/adapters/vercel-ai";
```

Each adapter takes the client plus a `user_id`, because `GET /v1/memories/context` requires `user_id`, `organization_id`, and `session_id`:

```python
memory = contextaMemory(m, user_id=user_id, token_budget=2000)
```
