# Example: Tutor Agent

A tutor that tracks a student's weak topics and adapts its explanations over time.

## What it does

- Tracks which topics a student struggles with
- Remembers quiz outcomes across sessions
- Adjusts explanation depth based on demonstrated level
- Lets truth maintenance correct a stale weak area once it is mastered

## Full code

```python
import asyncio
import os

from openai import AsyncOpenAI
from contexta_client import AsyncContexta

AGENT = "tutor-agent"

client = AsyncContexta.from_env()
openai = AsyncOpenAI()


async def tutor_turn(student_id: str, session_id: str, message: str) -> str:
    ctx = await client.context(
        user_id=student_id,
        session_id=session_id,
        token_budget=2000,
    )

    system_prompt = (
        "You are a personalized tutor.\n\n"
        f"{ctx.to_system_prompt()}\n\n"
        "Adjust your explanation based on the student's known weak areas. "
        "If they have struggled with this topic before, explain more thoroughly. "
        "If they have mastered it, go deeper or move to advanced concepts."
    )

    reply = (await openai.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": message},
        ],
    )).choices[0].message.content

    await client.observe(
        user_id=student_id,
        session_id=session_id,
        messages=[
            {"role": "user", "content": message},
            {"role": "assistant", "content": reply},
        ],
        metadata={"agent": AGENT},
    )
    return reply


async def record_quiz_result(
    student_id: str,
    session_id: str,
    topic: str,
    score: int,
    total: int,
    weak_areas: str = "",
) -> None:
    """Record a quiz result as an ordinary observation."""
    result_text = (
        f"Quiz result: {topic} - {score}/{total}. "
        f"Weak areas: {weak_areas or 'none'}"
    )
    await client.observe(
        user_id=student_id,
        session_id=session_id,
        messages=[
            {"role": "user", "content": result_text},
            {"role": "assistant", "content": f"Recorded quiz result for {topic}."},
        ],
        metadata={
            "agent": AGENT,
            "topic": topic,
            "score": score,
            "total_questions": total,
            "weak_areas": weak_areas,
        },
    )


async def main() -> None:
    student = os.environ["CONTEXTA_ACTOR_ID"]
    session = "33333333-3333-4333-8333-333333333333"

    await record_quiz_result(
        student, session, "Linear Algebra", 3, 10,
        weak_areas="eigenvectors, matrix multiplication",
    )

    reply = await tutor_turn(
        student, session,
        "Can you explain eigenvectors again? I'm still confused.",
    )
    print(reply)


asyncio.run(main())
```

## What was removed, and why

The original version called `client.register_schema(name="QuizResult", fields=[...])` and then stuffed a `_schema` object into observation metadata. **Both were fiction.** `POST /v1/schemas` does not exist, the SDK method raises `NotFoundError`, and the extractor ignores a `_schema` key in metadata.

Two working alternatives:

**Metadata as structured context** (what the example above does). The extractor reads the message text; the metadata is available to audit and telemetry.

**A behavioural directive** for things the tutor must always honour:

```python
await client.add_rule(
    user_id=student_id,
    rule="Never skip the worked example when explaining a new concept",
    title="Pedagogy rule",
    tags=["tutoring"],
)
```

## Mastery supersedes struggle

This is where the memory model earns its keep. A student who later says *"I finally understand eigenvectors"* produces a new fact for the same `subject`/`predicate`/`object` slot as the earlier "struggles with eigenvectors" fact. The structural slot key matches, so the old fact is closed with `valid_to = now()` and linked through `memory_version.superseded_by_id` — rather than both being live and the tutor hedging.

Get the lineage with `client.explain(memory_id=...)` and read `supersession_history`.

## Key takeaway

The tutor does not just remember facts; it remembers the student's learning *state*, and that state can change without accumulating contradictions.
