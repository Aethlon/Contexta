# Example: Coding Agent

A coding assistant that remembers a developer's stack preferences and past decisions across completely separate conversations.

## What it does

- Remembers preferred languages, frameworks, and databases
- Recalls past project decisions in a new thread
- Carries style preferences (type annotations, test patterns)
- Keeps different developers isolated

## Full code

```python
import os

from openai import OpenAI
from contexta_client import Contexta

AGENT_NAME = "coding-agent"
ASSISTANT_ID = os.environ["OPENAI_ASSISTANT_ID"]

client = Contexta.from_env()
openai = OpenAI()


def code_chat(user_id: str, session_id: str, message: str) -> str:
    # 1. Fetch context for this user
    ctx = client.context(
        user_id=user_id,
        session_id=session_id,
        token_budget=2000,
    )

    # 2. Run the assistant with that context
    thread = openai.beta.threads.create()
    openai.beta.threads.messages.create(
        thread_id=thread.id, role="user", content=message
    )
    run = openai.beta.threads.runs.create_and_poll(
        thread_id=thread.id,
        assistant_id=ASSISTANT_ID,
        additional_instructions=ctx.to_system_prompt(),
    )

    messages = openai.beta.threads.messages.list(thread_id=thread.id)
    reply = messages.data[0].content[0].text.value

    # 3. Observe the turn
    client.observe(
        user_id=user_id,
        session_id=session_id,
        messages=[
            {"role": "user", "content": message},
            {"role": "assistant", "content": reply},
        ],
        metadata={"agent": AGENT_NAME, "thread_id": thread.id},
    )

    return reply
```

`session_id` is a real Contexta session, distinct from the OpenAI thread id. The thread is disposable; the session is what makes the next call remember anything.

## What was removed, and why

The original version of this example called `client.register_policy(...)` with `store_rules`, `ignore_rules`, and `priority_weights`. **That endpoint does not exist** — `POST /v1/policies` was removed with the policy subsystem and the SDK method now raises `NotFoundError`.

What replaced it:

- **Filtering what gets stored** happens inside the pipeline, not via a registered policy. `add_rule()` writes decay-exempt behavioural directives through `observe()`.
- **Type classification** is the extractor's job, driven by `MemoryType` in `contexta/core/types.py`.

```python
# A behavioural directive, not a policy
client.add_rule(
    user_id=user_id,
    rule="Always run the linter before pushing",
    title="Pre-commit check",
    tags=["process"],
)
```

## One key per developer

`user_id` must equal the actor bound to your API key. To give two developers separate memory, mint two keys — one per (organization, actor) pair — and route each developer's requests through their own key. Sending a different `user_id` under one key returns `403`, not an empty result.

## Key takeaway

The agent remembers a preference stated in one thread and applies it in a thread that has never seen it. The durable identifier is the `user_id` bound to the key, and the `session_id` groups turns within it.
