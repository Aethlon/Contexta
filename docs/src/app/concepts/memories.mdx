# Memories

A **memory** is a discrete, typed unit of stored intelligence produced by the extractor from one or more observations. Memories are not vectors with a wrapper — each one carries a validity window, a fact slot, provenance, and a lineage trail.

## Storage

PostgreSQL with pgvector, in the `memory_record` table. Scoped by `organization_id` and `user_id`.

| | |
| :--- | :--- |
| Offline embedding column | `embedding_1024`, 1024 dimensions, `Qwen/Qwen3-Embedding-0.6B` |
| Online embedding column | `embedding`, 1536 dimensions, OpenAI `text-embedding-3-small` |
| Search text | `title + content + tags`, indexed as a `tsvector` with a GIN index |
| Rows in the `public` schema | 33, down from 57 before revision `020` |

Do not mix dimensions. Vectors are never padded or truncated; switching profiles needs a column migration or a volume reset.

| Type | Example |
| :--- | :--- |

| `skill` | "User knows Rust and Python" |
| `relationship` | "Alice is Bob's manager" |

| `custom` | Reserved |

The extractor may return a type outside this set; the pipeline normalises known near-misses (`travel` becomes `event`) rather than discarding the memory.

## Importance and confidence

`importance` combines emphasis, decision impact, and mention count. `confidence` derives from the source type. Both land on the memory and feed the retrieval quality prior.

A low-value extraction is dropped **before** it costs an embedding and a graph edge.

## Fact slots and truth maintenance

This is the part that makes memory *true* rather than merely accumulated.

When the extractor returns a `subject` / `predicate` / `object` triple, the pipeline hashes the canonicalised `subject` + `predicate` (+ `context`) + `object` into a structural slot key of the form `sfx2:<sha256>`. Two statements of the same slot therefore share a key.

> The slot names the **whole assertion**, so the object is part of the digest. A partial triple is refused rather than half-keyed: a row that cannot name its slot falls back to the legacy text hash rather than being guessed into someone else's slot.
>
> v1.5 originally shipped `sfx1:`, which hashed subject + predicate and left the object out on the theory that a slot is "who, about what" and a new value is a correction of that slot. That only holds if the predicate is exclusive — one live value per subject and predicate — and it is not. Measured over a 10-conversation ingest, 123 keyed rows resolved to 32 slots, `subject` was the literal string `"the user"` in all 123, and four mutually exclusive `uses` facts shared one slot. With `uq_memory_record_current_fact_slot` allowing one current row per slot, each new arrival closed the previous one: of 10 sampled supersession pairs, 0 were real contradictions and 8 were unrelated. A slot that collides on unrelated facts does not reconcile truth, it deletes it. `sfx2:` is the fix, and the version bump keeps every pre-existing `sfx1:` digest provably distinct from any new one instead of letting a stale digest alias onto a live slot.

If a correction arrives, `TruthSupersessionService`:

1. claims the slot (the incumbent is closed with `valid_to = now()` *before* the replacement is inserted),
2. inserts the new row,
3. records lineage through `memory_version.superseded_by_id`,
4. writes an audit entry.

`uq_memory_record_current_fact_slot` — a partial unique index over `(organization_id, user_id, fact_key)` restricted to `valid_to IS NULL` — makes this mandatory rather than conventional. A correction cannot coexist with what it corrects.

A rephrasing of the same fact is *not* a contradiction: the same slot hashes to the same key, so the value is compared and the row is left alone. Two genuinely different facts get two different slots and both survive — the index stops being the thing that decides which fact lives.

**Legacy keys.** Any extraction with no usable triple — which is every memory written before the triple existed, and any memory whose model omitted it — still gets a bare 64-hex text-hash key. Those are still produced and still supported. Coverage is measurable with `fact_key LIKE 'sfx2:%'`. An `sfx1:` key is a superseded structural key: still readable, never written, and worth backfilling.

## Lifecycle

| State | Meaning |
| :--- | :--- |
| `active` | Current truth. Default. |
| `warm` | Decayed from active after 30 days without a read. |
| `cold` | After 90 days. Excluded unless `include_cold: true`. |
| `archived` | Excluded unless `include_archived: true`. |

Thresholds are `CONTEXTA_DECAY_*` settings (30 / 90 / 180 days). Decay follows **read age**: every retrieval hit calls `touch_accessed()`, so a memory that keeps being useful never decays regardless of when it was written.

```python
memory.pin(memory_id)      # exempt from decay
memory.unpin(memory_id)    # resume normal decay
memory.archive(memory_id)  # soft-hide from retrieval
memory.restore(memory_id)  # back to active
memory.delete(memory_id)   # hard delete
```

## Inspecting one

```bash
curl http://localhost:8000/v1/memories/$ID -H "Authorization: Bearer $CONTEXTA_API_KEY"
```

```json
{
  "id": "…", "memory_type": "fact",
  "title": "…", "content": "…",
  "structured_data": {},
  "source_type": "user_explicit",
  "confidence": 1.0, "importance": 0.5167, "utility_score": 0.0,
  "memory_state": "active",
  "valid_from": "2026-09-27T01:23:46", "valid_to": null,
  "fact_key": "sfx2:…",
  "created_at": "…", "updated_at": "…", "last_accessed_at": null
}
```

`valid_to: null` means current. A superseded memory has it set, and `explain` shows what replaced it:

```bash
curl http://localhost:8000/v1/memories/$ID/explain -H "Authorization: Bearer $CONTEXTA_API_KEY"
```

```json
{
  "memory_id": "…",
  "source": {"source_type": "user_explicit", "session_id": "…"},
  "classification": {"memory_type": "fact", "tags": []},
  "scoring": {"confidence": 1.0, "importance": 0.5167, "utility_score": 0.0},
  "supersession_history": [
    {"id": "…", "content": "…", "valid_from": "…", "valid_to": "…", "superseded_by_id": "…"}
  ]
}
```

## Feedback

`POST /v1/memories/{id}/feedback` adjusts `utility_score` and `confidence` on the row in place. The separate `retrieval_feedback` table was dropped in revision `020` because no code read it — the live path mutates `memory_record` directly.

## Custom schemas

There is no custom schema registry. `POST /v1/schemas` and the SDK/CLI schema methods target a removed endpoint and will return `404`. Typed extraction is driven by the extractor's own contract, not by a runtime-registered schema.
