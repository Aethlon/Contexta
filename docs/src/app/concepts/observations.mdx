# Observations

An **observation** is the raw unit of input to Contexta: a conversation turn or tool event, submitted for asynchronous memory extraction.

## Accepted shape

```json
{
  "user_id": "…",
  "organization_id": "…",
  "session_id": "33333333-3333-4333-8333-333333333333",
  "messages": [
    {"role": "user", "content": "I prefer Postgres over Mongo"},
    {"role": "assistant", "content": "Noted, I'll prefer Postgres."}
  ],
  "occurred_at": "2026-09-20T09:00:00Z",
  "observed_at": "2026-09-20T09:00:02Z",
  "timezone": "Europe/London",
  "metadata": {"agent": "coding-agent"}
}
```

`user_id`, `organization_id`, `session_id`, and `messages` are required. `user_id` must equal the actor bound to your API key and `organization_id` must equal its organization; a mismatch is a `403`.

### Temporal fields

| Field | Meaning |
| :--- | :--- |
| `occurred_at` | When the thing happened |
| `observed_at` | When Contexta saw it |
| `event_at`, `event_start`, `event_end` | An explicit event window |
| `temporal_precision` | How exact the time is (`exact`, `day`, `month`, …) — alias `precision` accepted |
| `temporal_basis` | Where the time came from — alias `basis` accepted |
| `timezone` | IANA zone used to resolve relative expressions — alias `event_timezone` accepted |
| `source_start`, `source_end`, `source_span` | Span within the source — `span` accepted as an alias |
| `source_id`, `message_id`, `source_message_id` | Provenance pointers |

The point of keeping these apart is that expressions like *"yesterday"* and *"next month"* can be grounded without inventing a reference date. When Contexta cannot resolve a time, it records `unknown` rather than guessing.

## What happens after you send it

```bash
curl -X POST http://localhost:8000/v1/observations \
  -H "Authorization: Bearer $CONTEXTA_API_KEY" \
  -H "Content-Type: application/json" -d '{ … }'
```

`202 Accepted` with `{"job_id", "observation_id", "status": "accepted"}` — and only *after* the observation, its source turns, and an outbox event are committed. The nine-stage pipeline then runs: redact, extract, dedup, score, graph, reconcile, embed.

### Status

```bash
curl http://localhost:8000/v1/observations/$JOB_ID -H "Authorization: Bearer $CONTEXTA_API_KEY"
```

```json
{
  "job_id": "…", "observation_id": "…",
  "status": "completed",
  "attempt_count": 1,
  "outbox_status": "published",
  "last_error": null,
  "created_at": "…", "updated_at": "…", "completed_at": "…"
}
```

Also available as `/v1/observations/status/{id}` and `/v1/observations/{id}/status`.

## Idempotency

Send `Idempotency-Key` (or `X-Idempotency-Key`), or an `idempotency_key` field in the body, up to 255 characters. A replay with a different payload returns `409`. Both SDKs generate a key automatically on every write.

## Batches

`POST /v1/observations/batch` takes up to **100** observations, as a bare array or `{"observations": [...]}`.

```json
{
  "jobs": [{"job_id": "…", "observation_id": "…", "status": "accepted"}],
  "errors": [{"field": "[1].messages", "message": "Field required"}],
  "status": "accepted"
}
```

Invalid items are reported with index-qualified field paths; valid items still ingest.

## Redaction

A **fail-closed** gate runs at the head of the pipeline, before extraction. It scrubs API keys, JWTs, bearer tokens, passwords, OTPs, session cookies, and card numbers, replacing matches with `[REDACTED]`. Both the HTTP route and the orchestrator run it, and redaction is idempotent, so double-running it is a no-op.

The fail-closed part matters: if the gate itself errors, the observation is **rejected**. It never degrades into "no redaction".

```json
{"user": "my key is sk-abcdefghijklmnopqrstuvwxyz123456"}
```

lands as `my key is [REDACTED]`.

## Limits

| Dimension | Constraint |
| :--- | :--- |
| Body size | 1 MiB (`CONTEXTA_MAX_OBSERVATION_SIZE_BYTES`) |
| Batch size | 100 observations |
| Overlarge body | `422` `{"detail": "Payload exceeds maximum allowed size.", "errors": [...]}` |
| Malformed JSON | `422` `{"detail": "Invalid JSON payload."}` |
| Empty/invalid batch | `422` with the failing index |
| Storage unavailable | `503` |

## Policy

`policy` is recorded on the observation as an opaque string. **There is no policy registry to register into** — `POST /v1/policies` and the SDK/CLI policy methods target an endpoint that no longer exists and will return `404`. See the [API reference](/reference/api#endpoints-that-do-not-exist).
