# LoCoMo Retrieval Benchmark

This directory benchmarks Contexta's `RetrievalEngine` against the
[LoCoMo](https://github.com/snap-research/locomo) (**Lo**ng **Co**nversational
**Mo**ry) dataset: 10 multi-session synthetic conversations (~4,700 dialogue
turns total) with ~2,000 human-annotated QA pairs, each pointing at the
specific dialogue turn(s) that contain the answer.

## What this measures (and what it doesn't)

This is a **retrieval-only** benchmark. For every QA pair, we:

1. Ingest every dialogue turn in the conversation as a `MemoryRecord`
   (episodic memory type), embedded with Contexta's deterministic local
   embedding provider (SHA256-based, no network/API calls, fully
   reproducible).
2. Embed the question text the same way.
3. Call `RetrievalEngine.retrieve()` in-process (no HTTP layer, no DB —
   an in-memory fake repository, matching the pattern in
   `tests/test_retrieval_engine.py`) and take the top 10 ranked memories.
4. Check whether the gold evidence turn(s) for that question appear in the
   ranked results, and at what rank.

We report **Recall@1 / Recall@5 / Recall@10** and **MRR** (mean reciprocal
rank) of gold evidence turns, broken out by LoCoMo's 5 question categories.

**This does not run an LLM to generate an answer from retrieved context.**
Mem0 and Letta's published LoCoMo numbers are end-to-end scores: retrieve
context, generate an answer with an LLM, then judge answer correctness
(usually with another LLM as judge). That collapses retrieval quality and
generation quality into one number. Our retrieval-only numbers measure a
different, narrower thing — whether the *right memories surface at all* — and
are **not directly comparable** to Mem0/Letta's self-reported scores. See
`RESULTS.md` (generated by running the benchmark) for the actual numbers and
a side-by-side discussion of that gap.

## Why retrieval-only

Contexta's repository ships a retrieval engine (`contexta/core/retrieval/engine.py`),
not a bundled LLM answer-generation step — `context()` assembles a system
prompt from retrieved memories and hands it to *your* LLM. Benchmarking
answer generation would mean benchmarking whatever LLM we chose to plug in,
which mostly measures the LLM, not Contexta. Measuring retrieval directly
isolates the part of the stack Contexta actually owns.

## Category mapping

LoCoMo's `qa[].category` field is an integer 1-5, confirmed against the
vendored dataset:

| category | name | count | notes |
| --- | --- | --- | --- |
| 1 | single-hop | 282 | answer grounded in one dialogue turn (usually) |
| 2 | temporal | 321 | "When did X happen" — all questions are date/time-seeking |
| 3 | multi-hop | 96 | requires combining evidence across turns/sessions |
| 4 | open-domain | 841 | general factual recall questions |
| 5 | adversarial | 446 | has no correct answer in the conversation (`adversarial_answer` field instead of `answer`); the gold "evidence" points at the closest-but-wrong turn |

## Running it

```powershell
# one-time setup (see repo root .venv, isolated from the mingw64 python on PATH)
python -m venv .venv
.venv\Scripts\python.exe -m pip install "sqlalchemy[asyncio]==2.0.36" "pgvector==0.3.6" "pydantic==2.10.3" "pydantic-settings==2.7.0"

# dataset is vendored at benchmarks/locomo/data/locomo10.json (2.7MB, committed)
.venv\Scripts\python.exe benchmarks/locomo/run_benchmark.py
```

This writes `benchmarks/locomo/results.json` (raw) and `benchmarks/locomo/RESULTS.md`
(formatted table) and prints a summary to stdout. No network access, no
Postgres, no Redis — everything runs in-process against a fake in-memory
repository.

Runtime note: `RetrievalEngine`'s semantic scoring is pure-Python cosine
similarity computed per-candidate per-query with no vector index (by design —
production uses pgvector's HNSW index instead). Across ~4,700 turns and
~2,000 questions that adds up; a full run takes several minutes on a single
core.

## Dataset provenance

`data/locomo10.json` is vendored verbatim from
[`snap-research/locomo`](https://github.com/snap-research/locomo)
(`data/locomo10.json`, MIT-licensed dataset from the LoCoMo paper,
Maharana et al. 2024, "Evaluating Very Long-Term Conversational Memory of
LLM Agents"). 9 of 2,815 evidence references in the source dataset have
malformed dialogue IDs (e.g. `"D8:6; D9:17"`, `"D:11:26"`) — these are typos
in the upstream annotation, not something we introduced. The harness
extracts valid `D<session>:<turn>` patterns via regex and skips a question
entirely only if *none* of its evidence IDs resolve.
